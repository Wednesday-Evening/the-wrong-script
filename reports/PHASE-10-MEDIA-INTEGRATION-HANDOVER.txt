5. CREDITS AND LICENSING - THE HONEST POSITION
--------------------------------------------------------------------------------

assets/media/ASSET-CREDITS.txt records, per asset: original filename, bytes,
format, duration, intended placement, source page, creator, licence,
attribution and suitability.

  Established:      the files exist, are intact and playable; the owner supplied
                    them and authorised this integration.
  NOT established:  who made each asset, where it came from, under which licence,
                    whether attribution is required, whether public or
                    commercial use is permitted.

No asset is described anywhere in this project as "licensed", "royalty-free" or
"cleared". The studio-style words inside three audio filenames (sigmamusicart,
audiovisuaiseu, universfield) are NOT recorded as credits - that would be a
guess from a filename, and this report does not make it.

OWNER ACTION BEFORE ANY PUBLIC LAUNCH: for each of the six assets, record the
source page, the creator (if a credit is required), the exact licence, whether
attribution must be shown to visitors, and whether commercial use is allowed.
Until then treat all six as unverified for public release.

Removal is safe by design: every video block is poster-first and user-started,
every audio element is optional and off by default, and no room depends on any
asset to function. Deleting one reference degrades to a working page.

6. WHAT WAS INTEGRATED, ROOM BY ROOM
--------------------------------------------------------------------------------

A. LOBBY  (/)

   The decorative "reel" block in the introduction panel is now a real media
   figure: the abstract-motion loop, poster-first, muted, looping, playsinline,
   preload="none", aria-hidden with tabindex="-1" because it is decorative, and
   a visible control labelled "Play background motion" / "Pause background
   motion" with aria-pressed. It does not obstruct navigation or text.

   The cinematic piano was NOT used as Lobby ambience. The authorisation made
   that optional ("consider"), and section 4D places the piano with the Gallery
   music context. Adding it in both places would have produced the competing
   audio streams section 5 warns against. This is a recorded decision, not an
   omission.

B. THE NINTH BELL  (/stories/the-ninth-bell/)

   The lighthouse loop sits above the scene text as a silent loop, poster-first
   and user-started. Ocean waves are offered as optional atmosphere through a
   state-labelled control ("Ocean sound: off" / "Ocean sound: on"), off by
   default, preload="none", looping. Story text reads identically with the media
   unused.

   Preserved: all ten scenes, five endings, the deliberately early ending,
   choice logic, ending logic and the story's own save behaviour. Story files
   changed only by the added media block (24 added lines, no other edit).

C. THE RETURNS HATCH  (/stories/the-returns-hatch/)

   The library loop sits above the scene text. This is the only video with an
   audio track, so the markup carries `muted` as well as playing muted in
   script: no browser can start it with sound. No audio element was added, so
   nothing competes with the story.

   Preserved: all ten scenes, five endings, the early ending, choice and ending
   logic, save behaviour. Only the media block was added (16 added lines).

D. GALLERY  (/gallery/)

   The piano is attached to the "Cue 07: The Door Opens Twice" exhibit, inside
   the existing exhibit panel, and labelled there as supplied atmosphere - not
   as a recording of that cue. The audio block is hidden until an exhibit that
   carries audio is opened, the source is attached at open time, and playback
   stops when the panel closes or Escape is pressed. A text description is
   present, so the exhibit is complete without sound.

   Preserved: every exhibit, category, description and the browsing behaviour.

E. ARCADE  (/arcade/, /arcade/signal-path/, /arcade/lamplight/)

   One quiet click on a deliberate press, from a single shared player,
   preloaded on demand and throttled to one tick per 90 ms so holding a
   direction pad cannot machine-gun it. Off by default: the first press makes no
   sound. A visible "Interface sounds: off / on" toggle with aria-pressed sits
   on the Arcade library and both games, so sound can be disabled without
   reloading.

   Preserved: SIGNAL PATH's six levels, Lamplight's rooms, both save systems,
   move counting and completion behaviour.

8. PLAYBACK AND ACCESSIBILITY IMPLEMENTATION
--------------------------------------------------------------------------------

  - No autoplay anywhere, with or without sound. Every video is user-started;
    every audio element is off until pressed.
  - preload="none" on all video and audio, so a page entry does not pull
    megabytes of media. The 4.5 MB abstract-motion file is not fetched until the
    visitor asks for it.
  - Posters for all three videos, so an unstarted block is never an empty box.
  - playsinline on all three videos for mobile.
  - Controls are real <button> elements with state in aria-pressed and a text
    label that changes with state ("Play/Pause background motion", "Ocean
    sound: off/on", "Interface sounds: off/on"), so the state is not carried by
    colour alone.
  - One shared controller pauses other media before starting a new one, and a
    pagehide handler stops playback when the visitor leaves, so audio does not
    follow them across rooms.
  - Focus rings come from the existing project convention; the new controls use
    the same focus treatment as the rest of the site.
  - prefers-reduced-motion removes transitions and animation on the media
    figure; measured at 0s in the browser.
  - Sizing is responsive with no crop or distortion; the Lobby video measured
    348 px wide inside a 390 px viewport with 0 px page overflow.

12. LIMITATIONS AND OUTSTANDING ITEMS
--------------------------------------------------------------------------------

  1.  Licensing is unverified for all six assets. This is the most important
      open item in the phase, and it is an owner action, not a code defect.
  2.  The expected 4K filenames in the authorisation were not present; the
      actual uploads are 720p. The integration uses what exists. If the owner
      intended the 4K originals, they will need uploading and the references
      re-pointed.
  3.  Chromium only, emulated mobile only, no assistive technology (section 10D).
  4.  Media is served as-is. The 4.5 MB abstract-motion file is the largest
      single asset; preload="none" keeps it off the critical path, but a slower
      connection will still wait after the visitor presses play. No re-encode was
      performed, because the authorisation forbids degrading media for a size
      target without a stated reason and approval.
  5.  The Gallery piano is labelled as supplied atmosphere, deliberately not as
      a recording of Cue 07. If the owner wants a different exhibit pairing, it
      is a one-field change in gallery-exhibits.js.
  6.  Story rooms write their own story save keys on load. That is pre-existing
      Phase 9 engine behaviour, confirmed identical at baseline; media code
      touches no storage at all.
  7.  No interface-sound preference is persisted. Sound resets to off on each
      visit, which is the safe default, but the owner may later want a stored
      preference - that would need a new, separately authorised key.
  8.  No defect was found in the five rooms during this pass, so none was fixed.
