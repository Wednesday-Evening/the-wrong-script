  Hash mechanism      assets/js/archive.js, resolveHash(): runs on boot and on
                      every window "hashchange". A fragment is accepted if it is
                      one of the four section ids or an element inside
                      .file, .collection or .discovery; the target element gains
                      the class .is-target. An unknown fragment reveals the
                      hidden #hash-note with a recovery message and links to
                      #completed-files and the Lobby, without redirecting.

Consequence for testing: the Archive does not intercept clicks, does not use
history.pushState or replaceState, and does not block the browser's own history.
Back/Forward therefore operate on ordinary browser history entries created by
the fragment links, and the tests were written to observe exactly that.

F. DEFECTS AND LIMITATIONS
--------------------------------------------------------------------------------

F1  MINOR COSMETIC DEFECT — target markers accumulate within a session
    Status: OPEN. Not fixed, because this pass carries no authorisation to
    change application code.

    Reproduction:
      1. Open /archive/.
      2. Click the "Completed Files" jump link, then the "Discoveries" jump link.
      3. Observe that both #completed-files and #discoveries carry .is-target.
      4. Use Back and Forward; both markers remain.

    Observed:      multiple sections simultaneously carry .is-target
                   ([completed-files, discoveries]); after an entry deep link the
                   entry and the previous section both carry it.
    Expected:      only the currently addressed section or entry is highlighted.
    Cause:         assets/js/archive.js, resolveHash() adds .is-target to the
                   resolved target and never removes it from a previous target.
                   .is-target is styled in assets/css/archive.css as
                   box-shadow: inset 2px 0 0 var(--gold), so each stale marker
                   keeps a gold inset bar.
    Impact:        cosmetic and confined to one browsing session. It does not
                   break navigation, duplicate content, corrupt state, persist
                   anything, or raise errors; a reload leaves exactly one marker.
                   Back/Forward still restore the correct fragment.
    Suggested fix (not applied): remove .is-target from previously marked nodes
                   before marking the new target inside resolveHash().
    Authorisation required before changing assets/js/archive.js.

F2  FALSE-POSITIVE TEST FAILURE (harness defect, not an application defect)
    Recorded so the audit trail is complete.

    Run 1 reported: FAIL  B9 an unknown fragment still returns the Archive page
                    [status null]
    Cause:         page.goto() from /archive/#discoveries to
                   /archive/#not-a-real-entry is a same-document fragment
                   navigation, so Playwright returns no response object and the
                   asserted status was null. The page itself was correct: the
                   same run's later B9 checks passed (recovery note visible,
                   fragment preserved, catalogue intact).
    Resolution:    the assertion was corrected in the harness to verify the
                   document (readyState, #main, rendered entries, title) when no
                   response object exists. No application code was touched.
    Run 2:         PASS on the corrected assertion; the full suite exited 0.
