2. IMPLEMENTATION SUMMARY
--------------------------------------------------------------------------------
Two new destinations were added to the existing static site:

  /arcade/               The Arcade library — one honest featured cabinet.
  /arcade/signal-path/   SIGNAL PATH, a complete single-player grid puzzle.

SIGNAL PATH is an original game: a small signal unit must cross a dark grid,
collect every signal fragment on the level, and only then may step onto the
beacon. Six handcrafted levels, no timer, no lives, no score, no randomness.

Nothing else was rebuilt. The Lobby, the original film and The Stories were
left functionally intact; the only shared edits are the navigation entries
needed to reach the Arcade (listed in section 10).

The game is split into rules, data, page controller and styles:

  assets/js/signal-path-core.js     Rules, save validation, level parsing.
                                    No DOM, no storage, no timers — pure logic,
                                    which is what makes the dev check possible.
  arcade/data/signal-path-levels.js The six levels as data (cells, start,
                                    beacon, fragments, hint).
  assets/js/signal-path.js          Page controller: rendering, input, saving.
  assets/css/arcade.css             Arcade identity and the game's layout.
  assets/js/arcade-games.js         The cabinet catalogue (one record).
  assets/js/arcade-library.js       Renders the cabinet from the catalogue.
  assets/js/arcade-shell.js         Small-screen navigation, matching the Lobby.
  tools/verify-signal-path.js       Development check (see section 8).

No framework, package manager, dependency, build step, backend, database,
authentication or external service was introduced. The site remains plain
HTML/CSS/JavaScript served as static files.

5. GAME RULES AND LEVEL INVENTORY
--------------------------------------------------------------------------------
Rules as implemented in assets/js/signal-path-core.js:

  - One cell per move, using arrow keys, W A S D, or the on-screen pad.
  - Walls and the grid edge block movement. A blocked attempt does not change
    the position and does not increment the move counter.
  - Every fragment on the level must be collected before the beacon completes
    the level. Stepping onto a sealed beacon does nothing except report how
    many fragments remain — and that move still counts, because it was a real
    move.
  - The move counter increments once per valid move.
  - Restart level returns to the start cell with 0 moves and no fragments.
  - Undo last move restores position, fragments and move count. It is shown
    because the core keeps a real history stack; it is not decorative.
  - No timer, no lives, no score, no streaks, no failure state.
  - Completing a level unlocks the next relay; a completed level can be
    replayed. The final level has a genuine completion state and a replay.

Level inventory (verified solvable; route lengths are the shortest found by
the solver in tools/verify-signal-path.js):

  #  Name            Grid   Walls  Fragments  Start     Beacon    Moves
  1  Relay Room      5x5     17        1       (1,1)     (2,3)       3
  2  Twin Contacts   6x6     22        2       (1,1)     (2,4)       6
  3  Switchback      7x7     30        1       (1,1)     (3,5)      10
  4  Dead Signal     8x7     32        3       (1,1)     (5,5)      16
  5  Cold Relay      9x7     38        3       (1,1)     (7,5)      14
  6  The Beacon      9x9     46        4       (1,1)     (5,7)      20

Difficulty grows through grid shape, wall density and fragment placement, not
through new unexplained mechanics. Tiles are never distinguished by colour
alone: the board carries glyphs (S, diamond, beacon, unit) and a written legend,
and the cells have accessible labels.

On-screen pad buttons are 44px or larger targets and carry accessible names
("Move up", "Move left", "Move down", "Move right"). Focus is visible
(outline with offset) on links, buttons and pad keys.


6. SAVE KEY, SAVED FIELDS, VALIDATION AND RESET
--------------------------------------------------------------------------------
Save key:   wrong-script.arcade.signal-path.v1
Version:    1
Stored shape:
            { "v": 1, "unlocked": <number>, "completed": [<level numbers>],
              "best": { "<level>": <moves> } }
Stored fields are limited to progress: which relay is unlocked, which are
completed, and best move counts. No name, no identifier, no personal data.

Validation:
  - The reader accepts only the exact key, requires an object with a numeric
    version of 1, coerces unlocked into the 1..6 range, keeps only completed
    entries that are valid level numbers, and drops anything else.
  - Malformed, truncated or unexpected values do not crash the game and are
    not silently deleted. The game starts safely in memory at level 1 and
    replaces the save note with a plain explanation: the stored value could not
    be read, nothing has been deleted, and the old value stays until the player
    chooses "Reset progress".
  - A failed write (storage blocked) leaves the game playable for the visit and
    says so.
  - Storage being unavailable entirely is handled the same way.

Reset:
  - "Reset progress…" opens an inline confirmation with "Yes, reset progress"
    and "Keep my progress". Nothing is destroyed until the destructive choice
    is taken. After confirming, the message reads: "Progress reset. Only the
    first relay is open again."
  - The page states plainly that progress is saved in this browser only and
    does not sync to other devices.

Isolation: SIGNAL PATH never reads, writes or clears the original film's "tws"
key or the story key "wrong-script.story.the-ninth-bell.v1". See section 7.
